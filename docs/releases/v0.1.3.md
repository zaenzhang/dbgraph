# v0.1.3 — Reliability fixes

Release: v0.1.3. Local verification completed on 2026-10-21; publication results are tracked in the repair plan.

This patch addresses defects in DbGraph's existing SQL, retrieval, snapshot, and
release workflows. Features and suggestions from other projects remain deferred.

## SQL validation and analysis

- Check SELECT expressions, UPDATE assignments, nested queries, and qualified
  columns with their table aliases and query scopes. Another table's column can
  no longer make an invalid reference appear valid.
- Apply the same validation result in CLI and MCP. Local snapshots and the graph
  index are required. The CLI prints its report and returns exit code `2` for
  invalid SQL, or `3` when snapshot/index setup is missing.
- Report unsupported analysis explicitly. Validation never executes SQL and is
  not proof that a database would execute it successfully.
- Determine unbounded UPDATE/DELETE risks from the outer AST condition, so a
  nested WHERE clause cannot hide an unrestricted outer write.

## Search and context

- Preserve Unicode search terms and short identifiers. Nonmatching text returns
  no results; Chinese matching uses available names and descriptions without
  automatic translation.
- Estimate the whole pretty-printed context JSON, including semantic metadata,
  relationships, and suggestions. Token estimates remain approximate.
- Enforce `mcp.maxResponseChars` against the Unicode characters in tool-result
  text, excluding the transport envelope. The minimum is `64`; oversized results
  return `response_budget_exceeded` instead of broken JSON.

## Snapshots and recovery

- Keep separate source identities when multiple SQL files contain identical
  text, while fingerprints continue grouping equivalent workload signals.
- Publish snapshot JSON only after the index and SQL artifacts have been stored.
  A failed capture preserves the previous latest snapshot.
- Restore a missing index during sync even when the schema is unchanged. Sync
  still captures current metadata first and requires a reachable provider.
- Require a real previous snapshot for diff; a single snapshot is no longer
  compared with itself.

## Packaging and documentation

- Add the macOS Intel build to the release workflow, aligning it with the six
  targets already documented by the installers.
- Align the nested npm launcher package version with the release version.
- Update English and Chinese usage guides, configuration documentation, and the
  website with validation, budget, and recovery behavior.
- Repair website documentation links and supply the missing favicon asset.

## Verification

- Workspace: 152 tests passed; live PostgreSQL test had no configured connection and returned early.
- Formatting, workspace/all-target clippy with warnings denied, and CLI build passed.
- Isolated SQLite CLI/MCP smoke passed: invalid/valid SQL agreement, duplicate sources, Chinese/no-match search, full-context and MCP budgets, missing-index recovery, failure preservation and retry.
- Website: 17-page build passed; desktop navigation and mobile Chinese guide checks passed. Broken documentation links and missing favicon were repaired.
- Six-platform release builds and asset publication are separate from native installation/runtime verification. Live PostgreSQL, power-loss recovery and native runtime checks on all six platforms were not performed.
